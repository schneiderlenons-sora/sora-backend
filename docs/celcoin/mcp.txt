MCP 0.1.038 tools
Model Context Protocol
Servidor MCP que expõe a API v2 (Celcoin Open Finance) via Model Context Protocol. O fluxo principal é gerenciar consentimentos e consultar contas, cartões (incluindo recorrências e parcelamentos), empréstimos, financiamentos e investimentos vinculados. Listagens usam paginação por cursor (per_page + cursor), igual à API REST.
Endpoint
O servidor Open Finance Celcoin Server é servido via Streamable HTTP na rota abaixo. Requer plano Pro.
https://api.polp.com.br/mcp/open-finance-celcoin
Configuração
Use o mesmo par de credenciais da API REST (x-api-client / x-api-secret) nos headers HTTP do cliente MCP. Veja os exemplos no painel à direita para Claude Desktop, Cursor e outras IDEs.
Transporte: HTTP (Streamable HTTP / SSE)
Autenticação: API Key via headers
Plano: Pro (obrigatório)
Paridade REST: mesmos resources, paginação e autorização da API Celcoin v2
Paginação
As tools de listagem usam paginação por cursor, igual à API REST Celcoin. Não existe parâmetro page.
Entrada: per_page (default 15; 500 em tools de transação) e cursor (opcional).
Resposta: pagination.next_cursor, prev_cursor e has_more.
Próxima página: passe o next_cursor como argumento cursor na próxima chamada.
Veja o exemplo de resposta no painel à direita (Pagination Response).
Como funciona
Registre a URL do servidor e os headers no seu cliente MCP (Claude, Cursor, agente customizado).
O cliente descobre as ferramentas disponíveis via protocolo MCP (tools/list).
O modelo de IA escolhe a tool adequada e envia os argumentos (tools/call).
O servidor valida os parâmetros, executa a mesma lógica da API REST e retorna JSON estruturado.
Tools de escrita (write) são marcadas como destrutivas no protocolo. As demais são somente leitura (read).

create-consentwritePOST /consents
Cria um novo consentimento Open Finance (Celcoin) para uma instituição, com CPF/CNPJ, produtos opcionais e avoidDuplicates para reutilizar consents ativos com a mesma institution_id e documents.
Parâmetros
Field Type Description
institution_id * string (uuid) UUID da instituição (obtido em list-institutions).
cpf string CPF do titular (PERSONAL/BOTH) ou do operador/representante (BUSINESS).
cnpj string CNPJ da empresa. Obrigatório em BUSINESS; opcional em BOTH; proibido em PERSONAL.
cliente_user_id string Identificador externo do cliente (email, UUID, ID interno, etc.).
products string[] Produtos Open Finance. Atuais: ACCOUNT, CREDIT_CARD_ACCOUNT, CREDIT_OPERATIONS, INVESTMENTS, EXCHANGE. Legado (LOAN, FUND, VARIABLE_INCOME, …) ainda aceito, mas normalizado na gravação.
avoidDuplicates boolean Se true, reutiliza consent AUTHORISED/AWAITING_AUTHORIZATION com a mesma institution_id e documents (objeto inteiro); EXPIRED permite criar novo.
