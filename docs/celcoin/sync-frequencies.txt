Limites Operacionais
O ecossistema do Open Finance Brasil possui limites operacionais regulatórios que devem ser respeitados ao se consumir os dados de um CPF/CNPJ de uma instituição específica.
warning Reconectar a mesma conta não “reseta” o limite
Se você conectar várias vezes a mesma conta com o mesmo CPF/CNPJ na mesma instituição, cada sincronização consome o limite operacional do mês. Ao atingir o teto, os dados não serão atualizados até a virada do próximo mês. Prefira reutilizar o consentimento existente em vez de criar novos para o mesmo cliente.
Orientação
A cota é contada por CPF/CNPJ + instituição, não por consentimento. Siga estas regras para não estourar o limite do mês e manter os dados do seu cliente atualizados.
01 Crie o consentimento uma única vez por cliente e instituição
Cada POST /consents dispara a importação inicial do histórico (contas, cartões, transações, investimentos…), e essa importação consome a cota mensal do CPF/CNPJ naquela instituição. Criar o consentimento várias vezes para o mesmo cliente queima a cota a cada criação — ao atingir o teto, os dados não são atualizados até a virada do mês. Guarde o id do consentimento e reutilize-o. O POST /consents com x-consent-version: 3 já impede duplicados e reaproveita consentimentos rejeitados/expirados/revogados ou com link já aberto; na criação legada (v2, sem o header), envie avoidDuplicates: true na criação.
02 Para alterar produtos (permissões), atualize o consentimento em vez de criar outro
Os produtos de um consentimento só mudam com uma nova autorização no banco. Em vez de criar outro consentimento, chame POST /consents/{'{consent}'}/recreate com o novo products. O id da Polp e os recursos já sincronizados são mantidos — não há um segundo registro concorrendo pela mesma cota. O recreate também é o caminho para reconectar um consentimento EXPIRED ou REJECTED. O recreate só vale para consentimentos v2: na v3, use PATCH /consents/{'{consent}'} para trocar os products de um consentimento AUTHORISED, e POST /consents com x-consent-version: 3 para reconectar os demais.
03 A Polp atualiza os dados automaticamente — você não precisa forçar
Depois de autorizado, a Polp agenda cada recurso para sincronizar no intervalo que cabe na cota mensal (veja a coluna Atualização na tabela abaixo). Esse agendamento existe justamente para evitar que o limite estoure antes do fim do mês. Para ser avisado quando houver dados novos, use os webhooks em vez de consultar a API em loop.
04 Consentimentos duplicados deixam a atualização mais lenta
Se existirem dois consentimentos para o mesmo CPF/CNPJ na mesma instituição, a cota passa a ser dividida entre eles. Para não atingir o teto, a Polp espaça as sincronizações: um recurso que atualizaria a cada 2 horas passa a atualizar a cada 4 horas — e assim por diante, proporcionalmente ao número de consentimentos. Se você tem duplicados, revogue os excedentes com DELETE /api/v2/consents/{'{consent}'} (vale para v2 e v3) e mantenha apenas um.
05 O sync manual de saldo usa a cota do recurso de saldo
POST /accounts/{'{account}'}/balance/sync consulta a instituição em tempo real e consome a mesma cota mensal de account.balance usada pela sincronização automática. Com skipScheduleUpdate: false (padrão), a chamada substitui a próxima sincronização automática e não aumenta o consumo; com true, cada chamada é uma consulta extra. Use apenas quando o usuário pedir o saldo mais recente — nunca para polling.
Faça
Um consentimento por cliente + instituição
Rotas v3: PATCH para trocar produtos, POST para reconectar (v2: recreate)
Deixe a Polp sincronizar e escute os webhooks
Balance sync só sob demanda do usuário
Evite
Criar um novo consentimento a cada login/reconexão
Criar outro consentimento só para mudar produtos
Manter consentimentos duplicados ativos
Chamar balance sync em loop ou agendado
Como funciona
Cada recurso usa o enum ConsentSyncResource e uma faixa máxima do Open Finance.
A Polp agenda o sync no máximo permitido pela faixa — as taxas abaixo são a frequência efetiva aproximada.
Consulte o cronograma por consentimento em GET /consents/{'{consent}'}/sync-schedules (API v2).
Limites por recurso
Limite mensal é o teto regulatório do Open Finance — quando o recurso cobre mais de um endpoint, vale o menor (passe o mouse no recurso para ver os endpoints).
Atualização é o intervalo mínimo entre sincronizações da Polp: 31 dias (o mês mais longo) divididos pela cota mensal do recurso. Assim nenhum mês civil passa da cota, mesmo os de 31 dias.
